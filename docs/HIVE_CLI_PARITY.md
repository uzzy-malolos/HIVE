# HIVE CLI parity

Objective: bring HIVE CLI close to Claude Code, Grok Build, and Codex in interactive coding behavior and terminal feel, including MCP, skills, hooks, plugins, and image input. The common local workflows below are implemented. This records tested behavior and compatibility limits, without claiming identical products or equivalent model quality.

## Reference workflows

Official references checked on 2026-10-16:

- [Codex CLI](https://learn.chatgpt.com/docs/codex/cli): interactive repository work, saved chats, review, images, permissions, and external tools.
- [Codex developer commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli): in-session model selection and status.
- [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode): keyboard editing, history, paste, shell commands, and session controls.
- [Grok modes and commands](https://docs.x.ai/build/modes-and-commands): conversation management, model/context controls, tools, and extensions.
- [Grok keyboard shortcuts](https://docs.x.ai/build/keyboard-shortcuts): prompt editing, scrollback, session controls, and shell mode.

These products differ. HIVE must provide working equivalents with explicit capability boundaries; it must not copy a command label whose underlying behavior is absent.

## Compatibility limits

Latest verification: **1,118/1,118** core tests, zero failures/skips, lint and
core/desktop-shell/worker builds passed. Live Codex-managed ChatGPT/Astra and
native subscription-picker proof are recorded in
`test-results/cli-subscription-plugins-verification.json`, source snapshot
`58b9df89acc66aa30947968f40875bab23d1595e5d2bf67b0f1dd560a73ce5f9`.
The earlier dependency audit found ten high/eleven moderate baseline advisories;
the lockfile was not changed and no clean dependency-audit claim is made.

- HIVE retains its own modes, Queen orchestration and managed-worktree policy. [Full workspace forks](CLI_WORKTREE_FORKS.md) exclude ignored untracked/private/runtime files and reject links, submodules and unsupported indexes. Legacy task-cell forks retain metadata-only restrictions. Old fingerprints require explicit adoption; files are never auto-adopted. Compaction is local/extractive; transcript search returns matching entries.
- [Marketplace plugins](CLI_MARKETPLACES.md) support native bundles and compatible Claude skills, literal positional command arguments/canonical plugin slash names, explicitly selected final-response output styles, MCP definitions, five hook handler types on eleven events, specialist agents with trusted skill preloads, installed dependency requirements and stdio LSP. Named arguments/nested command namespaces, unlisted/asynchronous events, unsupported agent runtime metadata, automatic dependency fetching and npm/archive/private sources remain unsupported. Plugin-agent private MCP/hooks/permission declarations stay inert. This does not establish full competitor plugin-runtime compatibility.
- [MCP OAuth](CLI_OAUTH.md) uses current-user DPAPI on Windows; other embedding hosts must supply an OS-backed cipher. External account consent, remote revocation and unsupported OAuth flows remain separate. The 2026-07-28 lifecycle, MRTR, acknowledged POST/stdin subscriptions and modern task extension coexist with legacy background GET recovery and experimental 2025-11-25 tasks. Legacy HTTP+SSE, general JSON Schema, sampling tools/ambient context and other unimplemented extensions remain outside supported scope. See [advanced protocols](CLI_PROTOCOLS.md).
- Shell mode retains HIVE command/path/publication guards. Checkpoints cover built-in file edits and patches; shell/build/test side effects are not checkpointed.
- Session and restore locks are never stolen automatically. After a crash or forced worker termination, inspect the named lock and confirm its owner is gone before manual recovery. Displaced checkpoint originals and extension .backup files are retained, including writes through old open descriptors.
- Provider fixtures establish transport and workflow behavior. Actual Gemini 3.5 Flash-Lite and Codex-managed ChatGPT/Astra discovery, buffered/streaming output and exact file-write checks separately passed on 2026-10-17; [the provider evidence](CLI_PROVIDER_VERIFICATION.md) preserves earlier failed probes. The subscription adapter cannot enforce an output-token cap and rejects capped sampling/hook/strict-verification requests. It uses its own keyring account, never imported client tokens. Independent HIVE OAuth/inference client registration remains separate. These checks do not establish other accounts, model quality, vision, billing accuracy or production reliability. Packaged binaries were not rebuilt or published.

## Boundaries

- Preserve current user/peer changes and existing desktop/web work. No commits, publication, deployment or configuration changes are implied by implementing CLI behavior.
- Provider credentials and private reasoning never belong in transcripts, extension manifests, persisted events, or test artifacts.
- Cost/context figures must have real provenance or an explicit estimate label.
- External extensions are opt-in execution. Listing or discovering a project does not authorize running its hooks or MCP processes.
- Preserve the active objective across handoffs; do not mark this checklist complete while material rows remain open.
